# ravel-bcc

CLI-агент статической проверки документа требований до начала разработки.
Он читает документ (PDF, DOCX, Markdown, TXT), выделяет отдельные требования и проверяет
каждое из них, а затем весь набор, по критериям ISO/IEC/IEEE 29148:2018 (п. 5.2.5, 5.2.6) и
IEEE Std 830-1998 (п. 4.3). Результат — отчёт на русском. В отчёте есть ссылка на место в
документе для каждого нарушения и уточняющие вопросы к автору.

Хакатон BCC-HUB x MNU FinTech, задача «Агент проверки требований».

## Требования к окружению

- [uv](https://docs.astral.sh/uv/) и git. Python 3.12 (`.python-version`; `pyproject.toml` допускает
  `>=3.11`) uv скачает сам.
- Ключ Gemini API для основного режима (бесплатный тариф подходит) или запущенная Ollama для
  локального режима. Без них работает только `--provider none` (проверка установки).
- Tesseract **не обязателен**. Он нужен только для PDF-сканов без текстового слоя. Без него
  Markdown, TXT, DOCX и PDF с текстом читаются как обычно. Скан без текстового слоя без
  Tesseract не читается: прогон завершится кодом 1 (см. «Если что-то пошло не так»).

## Быстрый старт

macOS / Linux:

```bash
git clone https://github.com/bkht17/ravel-bcc.git && cd ravel-bcc
uv sync
cp .env.example .env        # затем впишите GEMINI_API_KEY в .env
uv run ravel check samples/requirements.md -o reports/report.md
```

Windows PowerShell:

```powershell
git clone https://github.com/bkht17/ravel-bcc.git; cd ravel-bcc
uv sync
Copy-Item .env.example .env   # затем впишите GEMINI_API_KEY в .env
uv run ravel check samples/requirements.md -o reports/report.md
```

Отчёт ляжет в `reports/report.md`, рядом появятся ещё три файла (см. ниже). Каталог `reports/`
создаётся сам. Справка по параметрам: `uv run ravel check --help`.

### Ключ LLM

1. Откройте <https://aistudio.google.com/apikey> и создайте ключ (хватит бесплатного тарифа).
2. Впишите его в `.env` в строку `GEMINI_API_KEY=…`. Файл `.env` в git не попадает.
3. Модель по умолчанию — `gemini-3.8-flash`. Её можно сменить в `GEMINI_MODEL` (файл `.env`)
   или параметром `--model`. Если основная модель перегружена или исчерпала свою квоту, агент
   переходит на запасные из `GEMINI_FALLBACK_MODELS` (по умолчанию `gemini-3.6-flash`, затем
   `gemini-3.5-flash-lite`); итоговая модель записывается в паспорт отчёта.
4. За один прогон агент делает не больше 50 запросов к LLM (`RAVEL_MAX_CALLS`, 0 — без
   ограничения). Ответы кэшируются в `.cache/llm`, повторный прогон того же документа не тратит
   квоту.

### Локальный режим (документ не покидает машину)

```bash
ollama pull qwen2.5:14b
uv run ravel check samples/requirements.md -o reports/report.md --provider ollama
```

### Без LLM: проверка установки

```bash
uv run ravel check samples/requirements.md -o reports/report.md --provider none
```

Работают только детерминированные проверки, без ключа и сети. Этот режим нужен, чтобы проверить,
что всё установилось, а не для сдачи: итог в нём **всегда** «Решение принять нельзя» (status
`undecided`), а код выхода для читаемого документа всегда 2, потому что требования не проверены LLM. На примере из
репозитория вывод такой:

```text
ravel 0.1.0: samples/requirements.md [без LLM]
  → segmenter
  → linter
  → critic
  → clarifier

Требований: 49 (метаданных: 12, примеров: 6), нарушений: 10, вопросов: 8
Отчёт: reports/report.md
Вопросы: reports/report.questions.yaml  JSON: reports/report.json  Трасса: reports/report.trace.jsonl
```

## Что получается на выходе

Для `-o reports/report.md` агент создаёт четыре файла. Во всех четырёх один и тот же `run_id`
(в отчёте — строка «ID прогона» в паспорте), новый на каждый прогон.

| Файл | Что внутри |
| :--- | :--- |
| `reports/report.md` | Отчёт: паспорт прогона, нарезка, проверка каждого требования и набора, вопросы, сводка, итог |
| `reports/report.json` | Те же данные в машиночитаемом виде (источник истины для отчёта) |
| `reports/report.questions.yaml` | Уточняющие вопросы к автору требований с полем для ответа |
| `reports/report.trace.jsonl` | Трасса агентов: шаг, время, вызовы LLM, попадания в кэш |

Идентификаторы в отчёте: `R-001…` — требования, `M-001…` — метаданные документа, `E-001…` —
примеры. У каждого вида своя нумерация. LLM проверяет как требования только `R-`; метаданные
и примеры в счёт покрытия не входят. Если в документе у требования был свой номер («Ф-1»,
«FR-12»), он сохраняется в колонке «В документе».

### Итог и коды выхода

Итог отчёта (раздел 7) бывает трёх видов:

- «Критичных и существенных дефектов не найдено; можно начинать» (`ready`);
- «Документ требует доработки» или «Начинать … нельзя» (`not_ready`);
- **«Решение о начале разработки и тестирования принять нельзя»** (`undecided`): проверка
  неполна, поэтому ни «можно», ни «нельзя» отчёт не утверждает. Причины перечислены в разделе
  «Ограничения прогона» и в итоге: проверка только правилами без LLM; требований не выделено;
  часть требований не проверена LLM; сбои LLM в прогоне (квота, сеть, таймаут, исчерпан бюджет
  запросов); документ прочитан частично.

| Код | Значение |
| :--- | :--- |
| 0 | Проверка полная: итог `ready` или `not_ready`. Найденные дефекты код выхода не меняют |
| 1 | Документ не прочитан (битый, зашифрованный, пустой, скан без распознаваемого текста, нет файла) или отчёт не удалось записать (выходной путь совпадает со входом или является каталогом, нет прав, диск). Если отчёт собрать можно, в нём указана причина |
| 2 | Итог `undecided` (причины выше), в том числе при `--provider none` для любого читаемого документа |
| 3 | LLM недоступен до начала прогона: нет ключа `GEMINI_API_KEY` или неизвестный провайдер |

Неверные параметры командной строки (например, несуществующая опция) тоже дают код 2: это
стандартная ошибка использования, отчёт при этом не создаётся.

## Если что-то пошло не так

**Нет ключа (код 3).** Агент не стартует и пишет:

```text
LLM недоступен: Не задан GEMINI_API_KEY. Скопируйте .env.example в .env и впишите ключ.
Запустите с --provider none, чтобы получить отчёт только по правилам.
```

Скопируйте `.env.example` в `.env` и впишите ключ. Значение `your_gemini_api_key_here` считается
незаданным. Если ключ отклонён сервером (401/403), это обнаружится уже в ходе прогона: в
отчёте будет сбой LLM и итог «принять нельзя» (код 2), а не код 3.

**Лимит бесплатного тарифа (HTTP 429).** Агент обрабатывает 429 сам и не падает:

1. При лимите запросов в минуту повторяет запрос (до 3 попыток, с паузой по подсказке
   провайдера). В терминале видны строки вида `… — повтор 2/3 через N с`.
2. Если квота модели исчерпана (дневная, нулевая на тарифе или лимит не снялся после
   повторов) и Gemini указал, что квота считается на модель (так на бесплатном тарифе), агент
   переходит на запасную модель из `GEMINI_FALLBACK_MODELS`: в терминале
   «…переключаюсь на gemini-3.6-flash».
3. Если квота кончилась у всех моделей, LLM отключается до конца прогона. Проверки правилами
   выполняются, отчёт записывается. В нём указаны сбои LLM, число непроверенных требований,
   итог «Решение … принять нельзя», код выхода 2.

Что делать: подождать (минутный лимит) или до следующих суток (дневной), затем запустить
прогон заново: ответы, уже полученные от LLM, лежат в кэше `.cache/llm` и квоту не тратят. Можно
сменить модель (`--model`) или перейти на `--provider ollama`.

**Нет сети.** Агент делает повторные попытки, затем отключает LLM до конца прогона. Отчёт
записывается по результатам проверок правилами, в нём указан сбой («Нет связи с Gemini» или
«Gemini не ответил за N с»), итог «принять нельзя», код 2. Таймаут одного запроса задаётся
переменной `RAVEL_LLM_TIMEOUT`. Для проверки установки без сети используйте `--provider none`.

**Итог «Решение принять нельзя» и код 2.** Это не ошибка программы, а честное «проверка
неполна». Причина указана в разделе «Ограничения прогона» в начале отчёта (нет LLM, сбой LLM,
часть требований не проверена, документ прочитан частично). Устраните её и запустите прогон
заново.

**Документ не прочитан (код 1).** PDF-скан без текстового слоя читается только с Tesseract (для
русского текста нужен языковой пакет `rus`). Без Tesseract, а также при нечитаемом результате
распознавания агент завершает работу с кодом 1 и объясняет причину. Так же завершаются
зашифрованные и повреждённые файлы.

**Отчёт не записан (код 1).** Если папка недоступна для записи или диск переполнен, агент
печатает «Отчёт не записан: …» и завершается с кодом 1. Старые файлы отчёта при сбое
остаются нетронутыми.

## Сданный прогон

> Появится при сдаче: каталога `submission/` в репозитории пока нет.

Готовый прогон для жюри будет лежать в каталоге `submission/`:

- `submission/report.md` — отчёт;
- `submission/report.json`, `submission/report.questions.yaml`, `submission/report.trace.jsonl`
  — сопутствующие файлы того же прогона (общий `run_id`).

Отчёт сгенерирован агентом на коммите, указанном в паспорте (строка «Версия агента»), и вручную
не правился.

## Как повторить прогон жюри

macOS / Linux:

```bash
git clone https://github.com/bkht17/ravel-bcc.git && cd ravel-bcc
uv sync
cp .env.example .env              # впишите GEMINI_API_KEY в .env
uv run ravel check samples/requirements.md -o reports/report.md
```

Windows PowerShell:

```powershell
git clone https://github.com/bkht17/ravel-bcc.git; cd ravel-bcc
uv sync
Copy-Item .env.example .env       # впишите GEMINI_API_KEY в .env
uv run ravel check samples/requirements.md -o reports/report.md
```

Свежий отчёт ляжет в `reports/report.md`. Он отличается от сданного `run_id` и датой, а
формулировки LLM могут немного отличаться. Проверка установки без ключа: добавьте
`--provider none` (ожидаемо: итог «принять нельзя», код 2).

## Уточняющие вопросы

Агент не только находит дефекты, но и формулирует вопросы, которые аналитик должен закрыть до
старта разработки. Ответить на них можно двумя способами.

В терминале — агент задаст вопросы и сразу перепроверит документ:

```bash
uv run ravel check samples/requirements.md -o reports/report.md -i
```

Через файл — для асинхронной работы с автором:

```bash
# 1. впишите ответы в reports/report.questions.yaml (поле answer)
# 2. перепроверьте:
uv run ravel check samples/requirements.md -o reports/report-v2.md --answers reports/report.questions.yaml
```

## Архитектура

```text
файл ─► Ingest ─► Document IR ─► Segmenter ─► Requirements
                                                  │
                     ┌────────────────────────────┼─────────────────────┐
                     ▼                            ▼                     ▼
              Linter (без LLM)          Checker (LLM, 5.2.5)   SetChecker (LLM, 5.2.6)
                     └────────────────────────────┼─────────────────────┘
                                                  ▼
                               Critic: цитата есть в тексте? дубли? порядок
                                                  ▼
                               Clarifier: вопросы автору (LLM или шаблон)
                                                  ▼
                       report.json ─► шаблон ─► report.md (атомарная запись)
```

- **Агент — это роль**: свой промпт (`src/ravel/prompts/`), своя схема ответа (Pydantic) и
  свой шаг в оркестраторе (`src/ravel/orchestrator.py`). Агенты общаются только через
  `RunContext`.
- **Каждое нарушение подтверждено дословной цитатой.** Critic ищет её в тексте; если цитата не
  нашлась, находка отбрасывается. Это главная защита от галлюцинаций.
- **LLM не пишет отчёт.** Модель возвращает JSON по схеме, а таблицы, счётчики и итог
  собирает код.
- **Воспроизводимость.** Температура 0, фиксированный seed, кэш ответов в `.cache/llm`.
  Ключ кэша — модель, версия промптов и сам запрос, поэтому повторный прогон даёт тот же отчёт.
- **Повреждённые файлы.** Формат определяется по сигнатуре байтов. Битый PDF восстанавливается,
  а для зашифрованного и скана без текста выводится понятная ошибка. Для битого DOCX текст
  достаётся из XML, кодировка определяется автоматически. Всё, что потеряно, перечисляется в
  разделе «Ограничения прогона».
- **Консистентность.** Все форматы сначала приводятся к нормализованному markdown и разбираются
  одним парсером. Отчёт и сопутствующие файлы пишутся атомарно.

## Разработка

```bash
uv run pytest
uv run ruff check src tests
uv run python eval/score.py reports/report.json   # полнота против эталона дефектов
```

Структура:

```text
src/ravel/
  cli.py            CLI (typer)
  orchestrator.py   порядок агентов, трасса, итог
  models.py         контракт данных между модулями
  ingest/           чтение pdf/docx/md/txt → Document IR
  segment.py        нарезка требований
  lint.py           правила без LLM
  agents/           Segmenter, Linter, Checker, SetChecker, Critic, Clarifier
  llm/              Gemini, Ollama, кэш, повторы
  prompts/          промпты агентов (версия в __init__.py)
  quotes.py         проверка цитат
  render.py         отчёт, questions.yaml, trace.jsonl
eval/               эталон дефектов и скрипт оценки
samples/            пример входного документа
```

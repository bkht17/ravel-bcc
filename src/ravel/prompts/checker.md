Задача: проверь КАЖДОЕ требование из списка отдельно по свойствам качественного требования
ISO/IEC/IEEE 29148:2018, п. 5.2.5:

- necessary — требование нужно, без него теряется функция или ограничение;
- appropriate — уровень детализации соответствует документу: нет лишних проектных решений
  (конкретная СУБД, фреймворк, внутренняя реализация там, где нужна только потребность);
- unambiguous — допускает только одно толкование (термины, единицы, границы и их
  включительность, часовые пояса, точка отсчёта времени);
- complete — описано полностью: условия, исключения, ошибки, граничные значения, что
  происходит при отказе (пропуск — только по порогу существенности из общих правил);
- singular — одно требование, а не несколько склеенных;
- feasible — реализуемо в разумных ограничениях;
- verifiable — можно однозначно проверить тестом: есть измеримый критерий, нет слов вроде
  «быстро», «удобно», «при необходимости» без числа;
- correct — точно отражает потребность, без технических ошибок (например, метод HTTP,
  тип поля, код ответа не соответствуют назначению);
- conforming — следует шаблону и стилю документа;
- traceable — у требования есть идентификатор или однозначное место, на которое можно
  сослаться (IEEE 830 4.3.8).
Также отмечай риски ИБ (criterion = security), если они видны из текста.

Как проверять:
- Если требование содержит несколько условий (через «и», «а также», перечисление, несколько
  предложений), разбери каждое условие отдельно: у каждого могут быть свои пропуски.
  Саму склейку отметь один раз как singular.
- requirement_ids — только ID проверяемого требования из списка. Цитаты бери из текста
  этого же требования.
- Если у требования дефектов нет, ничего по нему не возвращай. Пустой список findings —
  допустимый ответ. Не ищи дефекты ради количества.
- reviewed_ids — ID каждого требования пачки, которое ты проверил по всем критериям: и с
  дефектами, и без них. Требование без ID в reviewed_ids считается непроверенным, и в отчёте
  у него будет «не проверено», а не «нарушений нет».

# Оценка качества агента

Измерительный инструмент повторяет методику аудита жюри. С ним видно, стал ли агент лучше
после правки промптов или правил, и не надо полагаться на впечатление от одного отчёта.
Эталоны лежат здесь, вне пакета `src/ravel`: продуктовый код их не видит.

| Файл | Что внутри |
| :--- | :--- |
| `golden.yaml` | Эталон аудитора для `samples/requirements.md`: 23 дефекта, K1–K9 ключевые (вес 1,5), S1–S14 второстепенные (вес 1) |
| `golden_extra.yaml` | Наши прежние записи, которых нет у аудитора (11 шт.), и соответствие остальных старых записей пунктам аудитора |
| `foreign/library.md` + `library.golden.yaml` | «Чужой» документ: 9 абзацев о выдаче книг, 7 ловушек, 1 чистый абзац |
| `foreign/timer.md` + `timer.golden.yaml` | Контроль: 5 корректных требований к таймеру, ждём 0 находок |
| `foreign/rooms.md` + `rooms.golden.yaml` | Небанковская проверка обобщения: бронирование переговорных, заранее зафиксированы противоречие (G1) и пропуск (G2) |
| `foreign/converter.md` + `converter.golden.yaml` | Небанковский чистый контроль: конвертер длины, ждём 0 находок |
| `judgments.yaml` | Ручная разметка находок для точности: 1 / 0,5 / 0 |
| `score.py` | Оценка одного отчёта |
| `run.py` | Прогон агента на всех документах и оценка каждого отчёта (`--only` — выбрать) |

## Как пользоваться

Прогон и оценка одной командой. Провайдер по умолчанию `none`, LLM не вызывается:

```bash
uv run python eval/run.py
uv run python eval/run.py -p gemini        # с LLM; ответы кэшируются в .cache/llm
uv run python eval/run.py --score-only     # только пересчитать оценки по готовым отчётам
```

Отчёты пишутся в `reports/eval/{requirements,library,timer}.*` (каталог в `.gitignore`).
Сводка всех оценок попадает в `reports/eval/summary.json`. Сохраните её под своим именем,
и два прогона можно будет сравнить.

Оценка одного отчёта:

```bash
uv run python eval/score.py reports/eval/requirements.json
uv run python eval/score.py reports/eval/library.json --golden eval/foreign/library.golden.yaml
uv run python eval/score.py reports/eval/requirements.json --judge eval/judgments.yaml --json > run-a.json
```

| Опция | Что делает |
| :--- | :--- |
| `--golden PATH` | Эталон, по умолчанию `eval/golden.yaml` |
| `--judge PATH` | Ручная разметка для точности |
| `--json` | Весь итог в JSON: полнота, каждая запись, находки вне эталона, точность |
| `--weight K=2` | Переопределить вес записей по префиксу id (см. «Знаменатель» ниже) |
| `--tolerance N`, `--no-lines` | Допуск по строкам цитат вместо значения из эталона; отключить сверку строк |

`score.py` завершается с кодом 0 при любом счёте. Код 1 означает только ошибку входа:
нет файла или битый эталон.

## Методика

### Полнота (recall)

Каждая запись эталона даёт свой вес, если дефект найден целиком, и половину веса, если найден
частично. Иначе запись даёт 0.

```text
полнота = Σ набранного / Σ весов = Σ / (9 × 1,5 + 14 × 1) = Σ / 27,5
```

В выводе каждая запись помечена ✓ (целиком), ½ (частично) или · (не найдено), рядом стоят
F-номера совпавших находок. `F-005½` значит, что находка F-005 совпала с записью частично.

Как решается, что находка совпала с записью:

1. **Ключевые слова.** Альтернатива — это список регулярных выражений, и находка подходит,
   если совпали все. Поиск идёт по `title + explanation + suggestion + цитаты`, в нижнем
   регистре, «ё» заменено на «е». Выражение с префиксом `@` ищется только в словах агента,
   без цитат. Иначе цитата из документа, где стоит то же слово, засчитала бы чужую находку.
   В словах агента есть и метка `criterion=<критерий>`, поэтому можно требовать, например,
   `criterion=singular`.
2. **Место.** Хотя бы одна цитата находки (`quotes[].location`, «…, строка N») должна стоять
   не дальше `tolerance` строк от `lines` записи. Для основного документа допуск ±3, для
   чужого 0, потому что там абзацы идут через строку. `also_lines` — наши дополнительные
   якоря, у каждого в `note` записана причина.
3. **Уровень.** Совпадение с `full` засчитывает запись целиком, с `partial` — наполовину.
   Флаг `combine: true` означает, что частичные альтернативы, найденные хотя бы разными
   находками, вместе дают полное совпадение. Так, у K6 одна находка может сказать
   «404 нет в перечне», а другая — «404 под заголовком 403». `combine: N` значит, что хватит
   N разных частей: у S2 это два аспекта из четырёх.

Одна находка может закрыть несколько записей (например K7 и S3 про поле `enabled`), как
и у аудитора. Совпадение по словам — эвристика. Если находка явно про дефект из эталона, но
попала в список «вне эталона», расширьте выражения в эталоне, а не пересчитывайте вручную.
Перед правкой эталона полезно прогнать его на синтетическом отчёте: одна «идеальная»
находка на запись плюс отвлекающие находки рядом. Идеальный набор должен дать 100 %,
а отвлекающие не должны совпасть ни с чем. На текущем эталоне так и есть: 23 из 23,
перефразировки тоже 23 из 23, все 14 отвлекающих находок остались вне эталона.

### Знаменатель: 27,5 или 32

По формуле из задания знаменатель равен 9 × 1,5 + 14 × 1 = **27,5**. Аудитор пишет 32. Это
9 × **2** + 14 × 1, то есть в расчёте аудитора ключевой дефект весил 2, а не 1,5. Его 15,6 %
воспроизводятся точно:

```bash
uv run python eval/score.py reports/eval/requirements.json --weight K=2   # 5 / 32 = 15,6 %
```

По весу 1,5 те же находки дают 4,25 / 27,5 = 15,5 %. Основной считается формула 27,5, потому
что так записано в эталоне, а `--weight K=2` нужна для сверки с цифрой аудитора.

### Точность (precision)

Аудитор ставил каждой находке 1 (верно), 0,5 (частично) или 0 (неверно) и делил сумму на
число находок. Здесь так же. Оценки пишутся в `judgments.yaml`:

```yaml
b4bb4042ec: 0.5  # F-007 … причина
```

Ключ — первые 10 символов SHA-1 от `(criterion, нормализованная первая цитата)`. F-номера
меняются между прогонами, а ключ остаётся, пока находка про то же место и тот же критерий.
Если находки нет в разметке, но она совпала с эталоном, она считается верной (1). Остальные
идут в «без оценки», и `score.py` печатает для них готовые строки, которые остаётся вставить
в `judgments.yaml` и проставить оценку.

Список «Находки вне эталона» — кандидаты в шум. Каждую надо посмотреть глазами: это либо
ложное срабатывание (0), либо дефект, которого нет в эталоне (1 в разметке; если дефект
важный, его стоит добавить в `golden_extra.yaml`).

### Чужие документы — проверка на подгонку

Аудитор проверял агента на незнакомом тексте: 9 абзацев о библиотеке с 7 ловушками. Нашлась
1 ловушка из 7, и это сочли признаком подгонки под один документ. `foreign/library.md`
повторяет эту проверку:

| ID | Ловушка | Строка |
| :--- | :--- | :--- |
| L1 | Бронь 24 часа в одном абзаце и 48 часов в другом | 5, 13 |
| L2 | Размытое «работать быстро» | 9 |
| L3 | Составное «выдать книгу, списать штраф и отправить SMS» | 7 |
| L4 | Возврат без негативного сценария | 11 |
| L5 | Проектное решение «хранить в PostgreSQL» | 15 |
| L6 | Неопределённый «золотой читатель» | 17 |
| L7 | SMS с датой возврата требуется дважды разными словами | 7, 19 |

Строка 3 (срок выдачи с примером дат) чистая и указана в `clean_lines`. Находка оттуда,
не совпавшая с эталоном, помечается «← чистая строка», то есть это ложное срабатывание.
Седьмую ловушку (дубль) пришлось опереть на третью (составное требование): девять абзацев
иначе не вмещают семь ловушек и чистый абзац.

`foreign/timer.md` — контроль: 5 корректных требований, эталон пуст. Каждая находка здесь —
кандидат в ложное срабатывание.

## Базовая линия

Прогон 2026-11-26 без LLM (`uv run python eval/run.py`, провайдер `none`, агент
`0.1.0 (9ab302e-dirty)`, промпты `2026-11-26.1`; в `-p none` работают только правила `lint`):

| Документ | Полнота | Точность (`judgments.yaml`) | Находок | Вне эталона |
| :--- | :--- | :--- | ---: | ---: |
| `samples/requirements.md` | 4,25 / 27,5 = **15,5 %** (по шкале аудитора 5 / 32 = 15,6 %) | 10,5 / 11 = 95,5 % | 11 | 5 |
| `foreign/library.md` | 1 / 7 = **14,3 %** | 1 / 1 = 100 % | 1 | 0 |
| `foreign/timer.md` | — (эталон пуст) | — | 0 | 0 |

- **Основной документ.** Полностью найдены K3 (GET для записи) и S7 (типы полей), частично
  K6 (404 вне перечня), S3 (тиыны и тенге) и S8 (200 «Created»). Не найдено 18 из 23,
  в том числе 7 из 9 ключевых. Все логические противоречия (K1, K2, K9) правилами не ловятся.
- **По нашим старым записям** (`golden_extra.yaml`): 3,5 / 11 = 31,8 %. Это заглушки,
  пустые таблицы и Content-Type: их правила и ловят.
- **Чужой документ.** Найдена только L2 («быстро» есть в словаре размытых слов), как и у
  аудитора, 1 из 7.
- **Точность.** Наша разметка даёт 10,5 / 11, аудитор на тех же 11 находках поставил 8,5 / 11.
  Его оценки по каждой находке нам не известны. Пока их нет, наша точность — верхняя
  граница; когда появятся, внесите их в `judgments.yaml`.

## Спорные места эталона аудитора

- **S6.** Аудитор пишет: «проверок „включено“ нет в шагах логики». Но шаг 3 (строка 119)
  проверяет переключатель. Нет проверок из Ф-1: что карта активна и что её валюта KZT. Эталон
  ищет именно их.
- **K3.** Строки аудитора 103–104, 109 и 120 не включают таблицу query-параметров
  (142–144), где `cardId` и сумма объявлены в строке запроса. Эти строки добавлены
  в `also_lines`.
- **K5.** Диапазон 169–180 захватывает строки 174–176 (описания 401, 403 и 500), к ошибке
  суммы они не относятся. По существу важны 121, 163, 169–172 и 178–180.
- **K1 и K9** стоят на одних строках 39–40 и пересекаются по смыслу. Одна находка может
  закрыть обе записи, если в ней есть и противоречие с «максимум один push», и случай
  «сумма уже выше нового порога».
- **S3.** Что значит «пропуски полей», аудитор не уточнил. Здесь это поля API
  (`enabled`, `limit_kzt`), которых нет в требованиях к данным (строка 49).

## Как добавить или поправить запись

```yaml
- id: S15
  weight: 1
  lines: [52, 120-121]      # строки документа; «a-b» — диапазон
  what: Коротко суть дефекта
  full:
    - ['@ключев\w* слов', 'ещ[её] одно|вариант']   # все выражения альтернативы должны совпасть
  partial:
    - ['@половин\w* сути']
  combine: true             # необязательно: частичные части вместе = полное совпадение
  note: почему lines/also_lines именно такие
```

После правки прогоните `uv run python eval/run.py --score-only` и проверьте, что прежние
совпадения не пропали.
